# tools/ntag

NTAG 424 DNA 태그를 개인화하는 로컬 도구. **백엔드 배포 이미지에 들어가지 않는다** —
USB 리더가 꽂힌 사람 노트북에서만 돌리므로 의존성도 여기서만 관리한다.

## 준비

```bash
pip install -r tools/ntag/requirements.txt
```

macOS는 별도 드라이버 없이 기본 PC/SC 스택을 쓴다. 리눅스는 `pcscd`가 떠 있어야 한다.

## 리더 호환성 확인 (읽기 전용)

개인화를 구현·실행하기 전에 반드시 먼저 통과시켜야 하는 단계다. 태그에 아무것도 쓰지 않고,
NDEF 애플리케이션을 SELECT한 뒤 GetVersion으로 UID만 읽는다.

```bash
python -m tools.ntag.probe
```

태그를 리더에 올려둔 상태로 실행한다.

| 종료 코드 | 의미 |
|---|---|
| 0 | 이 리더로 APDU가 오간다. 개인화 구현으로 넘어가도 된다 |
| 1 | 리더는 붙었지만 태그와의 APDU가 실패했다 — 리더를 바꿔야 할 수 있다 |
| 2 | pyscard 미설치, 리더 없음, 또는 카드 연결 실패 |

ACR122U는 PN532 앞에 USB-CCID 컨트롤러가 있어 PN532 고유 기능을 온전히 쓰지 못한다.
그래서 nfcpy 문서는 이 리더를 권장하지 않는다. 다만 여기서 쓰는 명령은 전부 짧은
ISO 7816 wrapped APDU(`90 xx 00 00`)라 표준 PC/SC 경로로 오간다 — 이 스크립트가
확인하려는 것이 정확히 그 점이다.

## 태그 개인화

리더 확인이 끝난 뒤에만 실행한다.

```bash
export NTAG_MASTER_KEY=$(grep '^NTAG_MASTER_KEY=' .env | cut -d= -f2)
python -m tools.ntag.personalise --tag-id <tag_id>
```

기본 실행은 **키를 회전하지 않는다**. UID를 읽고, 바인딩을 등록하고, NDEF와 SDM 설정까지만 한다.
장비 토큰은 인자로 받지 않는다 — 바인딩 응답으로 서버가 알려준다. 오타 하나로 UID와 토큰이
어긋난 태그가 구워지는 것을 막기 위해서다.
이 상태에서 폰으로 태깅해 URL이 `?uid=..&ctr=..&cmac=..`로 채워져 열리는지 직접 확인한다.

확인이 끝나면 회전한다.

```bash
python -m tools.ntag.personalise --tag-id <tag_id> --rotate-key
```

`--rotate-key`는 **되돌릴 수 없다.** 마스터키를 잃으면 그 태그는 영구히 못 쓴다.

회전 전에 도구가 **태그를 직접 읽어** CMAC 구성을 확인한다. SDM이 켜진 태그를 읽으면
칩이 UID·카운터·CMAC을 채워 돌려주므로, 그것을 서버와 같은 함수(`backend.ntag424`)로 검증한다.
맞지 않으면 회전하지 않는다.

이 확인을 서버로 할 수 없는 이유가 있다. 회전 전의 태그는 아직 **공장 키**로 CMAC을 만드는데
서버는 파생 키로 검증하므로, 서버를 통한 확인은 원리상 통과할 수 없다. 그래서 회전 전 검증은
반드시 리더로 직접 읽어서 해야 한다.

### 순서를 이렇게 잡은 이유

| 단계 | 되돌릴 수 있나 | 왜 이 순서인가 |
|---|---|---|
| UID 읽기 | 쓰기 없음 | 실패해도 태그는 백지다 |
| 바인딩 등록 | 예 | 먼저 해두면 뒤가 실패해도 매핑만 지우면 된다. 서버가 장비 토큰을 알려주므로 오타가 끼어들 자리도 없다 |
| NDEF + SDM 설정 | 예 | 아직 공장 키라 몇 번이든 다시 쓸 수 있다 |
| 태그를 읽어 CMAC 확인 | 쓰기 없음 | 구성이 틀렸다면 여기서 드러난다 |
| 키 회전 | **아니오** | 앞이 전부 확인된 뒤에만 |
| 폰으로 태깅 | — | 회전까지 끝난 뒤의 최종 확인. 여기서 대여 화면이 열리면 완료다 |

### 중간에 실패했다면

그대로 다시 실행하면 된다. 도구가 태그와 서버에 물어 상태를 판별하고, 남은 일만 한다.

| 판별 | 처리 |
|---|---|
| 백지 | 바인딩 → NDEF 기록 → SDM 설정까지 하고 멈춘다 |
| 설정됨, 탭 기록 없음 | NDEF를 다시 굽지 않는다(설정 후에는 쓰기가 키 0 보호로 바뀐다). 폰으로 태깅하라고 안내한다 |
| 설정됨, 탭 성공 | `--rotate-key`로 회전하면 끝이라고 안내한다 |
| 회전 완료 | 더 할 일이 없다 |
| 다른 장비에 묶인 UID | 중단한다. UID는 재바인딩하지 않는다 |
| 알 수 없는 키 | 공장 키도 파생 키도 아니다. 이 도구로는 복구 불가 |

상태 판별은 **키 2**로 인증을 시도해 이뤄진다. 키 0은 공장값 그대로 두기 때문에, 키 0으로 물으면
이미 완성된 태그도 백지로 보인다.

바인딩 등록은 같은 (장비, UID) 쌍이면 몇 번을 보내도 200이라, 재실행이 안전하다.

## 키 파생

태그별 키는 마스터키와 UID에서 파생하며 어디에도 저장하지 않는다. 이 도구는 파생 로직을
복제하지 않고 `backend.ntag424.derive_tag_key`를 그대로 부른다 — 두 쪽이 한 바이트라도
어긋나면 태그가 물리적으로 멀쩡한 채 영원히 인증에 실패하기 때문이다.
`tests/test_key_agreement.py`가 이 일치를 못박고 있다.

설계는 `docs/trd/2026-08-30-ntag424-sdm-authenticated-tagging.md`에 있다(로컬 전용).
