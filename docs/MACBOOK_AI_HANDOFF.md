# MacBook AI Agent Handoff

## Goal

Recreate this project on a new MacBook without copying old runtime data.

What must be preserved:

- source code
- project structure
- backend/frontend/blockchain behavior
- PostgreSQL schema

What does **not** need to be preserved:

- old PostgreSQL rows
- old Besu chain data
- generated validator keys
- local `.env` secrets from the previous machine

## Current Repo Readiness

This repo is prepared for fresh-machine setup.

Key files:

- `backend/requirements.txt`
- `rtls/requirements.txt`
- `.env.example`
- `frontend/.env.example`
- `rtls/.env.example`
- `blockchain/besu/.env.example`
- `database/schema.sql`
- `scripts/init-db.sh`
- `docs/POSTGRES_SETUP.md`
- `docs/MACBOOK_PRIVATE_REPO_MIGRATION.md`

## Required Manual Setup On MacBook

Install these first:

- Git
- Python 3.10+
- Node.js 18+
- PostgreSQL
- Docker Desktop
- OpenSSL

## Fresh Setup Order

### 1. Clone

```bash
git clone <repo-url>
cd <repo-name>
```

### 2. Backend

```bash
cp .env.example .env
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
```

### 3. PostgreSQL schema

Create the database first, then apply the schema.

Example:

```bash
createdb rtls
bash scripts/init-db.sh
```

If `createdb` is unavailable, use:

```bash
psql postgres -c "CREATE DATABASE rtls;"
bash scripts/init-db.sh
```

### 4. Run backend

```bash
source .venv/bin/activate
uvicorn backend.server:app --reload
```

### 5. Frontend

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

### 6. RTLS reader setup

Only needed if RTLS device simulation or reader code is used.

```bash
source .venv/bin/activate
pip install -r rtls/requirements.txt
cp rtls/.env.example rtls/.env
```

Important:

- set `RTLS_SERVER_URL` in `rtls/.env` to a backend address reachable from the reader device

### 7. Besu private chain

```bash
bash blockchain/besu/scripts/generate-network.sh
cd blockchain/besu
docker compose up -d
```

## Important Implementation Notes

- Backend reads root `.env`
- RTLS reader reads `rtls/.env`
- Frontend reads `frontend/.env`
- Besu runtime `.env` is generated by `generate-network.sh`
- Database schema is versioned in `database/schema.sql`
- `usage_history` may be empty on a fresh setup; that is acceptable

## Known Limits

- Fresh setup is prepared, but end-to-end runtime validation has not been executed in this session
- Existing production-like data is not migrated
- Existing Besu chain state is not migrated

## If Something Breaks First

Check these in order:

1. `.env` values are present and point to the right hosts/ports
2. PostgreSQL database exists and `database/schema.sql` was applied
3. Backend can connect using `DATABASE_URL`
4. Frontend points to the backend via `VITE_API_BASE_URL`
5. Docker Desktop is running before starting Besu
